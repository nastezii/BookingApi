# Лабораторна робота 3 

## Що змінилося у структурі проєкту

У лабораторній роботі 3 було розділено логіку запису та читання даних за принципом CQS.

У Application Layer були створені окремі:

- Commands
- Queries
- Handlers
- ReadModels

Раніше контролери напряму використовували сервіси, які одночасно виконували і читання, і зміну стану системи. Тепер операції запису та читання розділені.

---

## Переваги CQS

### 1. Краща структура коду

Кожен handler виконує лише одну задачу.

Наприклад:
- CreateBookingHandler відповідає лише за створення бронювання
- GetBookingsHandler відповідає лише за читання бронювань

---

### 2. Просте тестування

Commands можна тестувати окремо unit-тестами.

Queries можна тестувати integration-тестами через HTTP endpoint.

---

### 3. Менше логіки у контролерах

Контролери стали “тонкими”:
- створюють Command або Query
- передають їх у Handler
- повертають результат

---

### 4. Queries повертають DTO

Для читання використовуються ReadModels, а не доменні сутності.

Це дозволяє:
- повертати лише потрібні поля
- не прив’язувати API до доменної моделі
- спростити оптимізацію запитів

---

## Недоліки CQS

### 1. Більше файлів

Для кожної операції потрібно створювати:
- Command або Query
- Handler
- DTO / ReadModel

Через це структура стає більшою.

---

### 2. Складніша архітектура

Для маленьких проєктів CQS може бути надлишковим.

---

## Чим Command / Query Handler відрізняється від Service

Service зазвичай містить багато різної логіки.

Handler виконує лише одну конкретну операцію.

Наприклад:
- один handler створює бронювання
- інший повертає список бронювань

Через це код стає простішим для підтримки.

---

## Як CQS впливає на розширюваність

Нові функції можна додавати без зміни існуючих handler’ів.

Наприклад:
- CreateBookingCommand
- DeleteBookingCommand
- UpdateBookingCommand

кожен має власний handler.

---

## Чому ReadModel відрізняється від доменної моделі

Доменна модель містить бізнес-логіку та інваріанти.

ReadModel використовується лише для повернення даних клієнту.

Це дозволяє не залежати від внутрішньої структури домену.
