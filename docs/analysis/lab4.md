```text
Мета

У цій лабораторній роботі було реалізовано
синхронну та асинхронну взаємодію між
компонентами системи бронювання.

Було виділено окремий допоміжний компонент
для надсилання повідомлень та реалізовано:

- синхронний виклик через інтерфейс
- асинхронну взаємодію через Event Bus
```

```text

```

```text
Notification Service
```

```text
INotificationService
NotificationService
```

```text
Компонент відповідає за відправку
повідомлень після створення бронювання.
```

```text
Синхронна комунікація
```

```text
CreateBookingHandler
→ NotificationService
```

```text
Особливості
```

```text
- виклик відбувається в тому ж потоці
- основна операція чекає завершення допоміжної
- handler залежить лише від інтерфейсу
- використовується Dependency Injection
```

```text
Приклад
```

```csharp
await _notificationService.SendAsync(
    "SYNC: booking created");
```

```text
Схема взаємодії
```

```text

```

```text
Публікація події
```

```csharp
await _eventBus.PublishAsync(
    bookingCreatedEvent);
```

```text
Особливості
```

```text
- handler не викликає NotificationService напряму
- подія публікується після завершення операції
- Event Bus передає подію subscriber
- компоненти менше залежать один від одного
```

```text
Реалізовані події
```

```text
BookingCreatedEvent
```

```text
Подія містить:

- UserId
- Description

Подія описує факт,
який уже відбувся.
```

```text
Переваги асинхронного підходу
```

```text
- менша зв’язаність між компонентами
- легше масштабувати систему
- можна додавати нові subscribers
- handler не залежить від конкретної реалізації
- простіше інтегрувати зовнішні сервіси
```

```text
Порівняння підходів
```

| Критерій | Синхронний | Асинхронний |
|---|---|---|
| Час відповіді | довший | швидший |
| Зв’язаність | більша | менша |
| Масштабованість | нижча | вища |
| Простота реалізації | простіше | складніше |
| Відмовостійкість | нижча | вища |

```text
Висновок
```

```text
У ході лабораторної роботи було
реалізовано два способи взаємодії
між компонентами системи.

Синхронний підхід є простішим,
але створює сильнішу зв’язаність
між компонентами.

Асинхронний підхід через Event Bus
дозволяє будувати більш гнучку
та масштабовану архітектуру.

Було продемонстровано використання:

- Dependency Injection
- Event-Driven Architecture
- Event Bus
- Handlers
- helper-компонентів

У результаті система стала
більш розширюваною та ближчою
до production-підходів.
```
